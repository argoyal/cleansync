# 0.5.1: the minor findings left from 0.5.0

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Each task is a batch of small, independent fixes. Every fix gets a test that fails first. Steps are TDD per fix.

**Goal:** Fix the minor findings the 0.5.0 reviews deferred, without changing any behaviour the owner approved.

**Specs these fixes serve:**
- `docs/superpowers/specs/2026-10-13-mail-panel-and-search-design.md`
- `docs/superpowers/specs/2026-10-13-running-rules-design.md`
- `docs/superpowers/specs/2026-10-13-bulk-offload-design.md`

## Global Constraints
- **No behaviour change beyond each listed fix.** All safety rules from 0.5.0 stay:
  - no mail leaves Gmail without a checked copy;
  - CleanSync never removes its copy of mail still in Gmail;
  - every Delete forever needs the typed count;
  - Delete forever rules are never Automatic.
- **Copy:** plain everyday words in every text.
- **Checks:**
  - backend: `cd backend && uv run pytest -q`, `uv run ruff check . && uv run ruff format --check .`
  - frontend: `cd frontend && npm test -- --run && npm run lint && npm run typecheck`
- **Git:** never use `git stash`.

## Left out on purpose (owner-approved behaviour)
- **Picking a thread by hand acts on the whole thread.** This is how picks worked before 0.5.0.
- **Undo doesn't mark a mail as moved back.** A later run can plan it again, and that run still needs approval.

### Task 1: Rules and runs (backend)

Fix each of these, each with a test:
1. **Sender approval counted twice.** In `Decisions.correct()`, correcting to a Delete forever rule counts the sender approval twice, because `learn` runs in `correct` and again in `approve`. Skip `learn` in `correct()` when the target is Delete forever, so `approve()` counts it once.
2. **Delete forever Activity grouping.** `record_rule_forever` (`backend/app/services/mail/forever.py`) groups mails for 10 minutes counted from the first record's time.
   - Count it from the last merge instead. Keep the last time in the record's payload.
   - Stop importing the private `_redact_value`. Make a public redaction helper in `events/bus.py` and use it.
   - Test grouping expiry, and a different rule starting a new record.
3. **Wrong message for a replaced run.** Approving a run that another tab or a card Run already replaced says "Wait until the preview is finished.". Say plainly that a newer run replaced it.
4. **"Apply 0 changes" after a rule is deleted.** If a run's rule is deleted while its match list is open, the approve button can read "Apply 0 changes". Make `preview`/`run` leave out PLANNED decisions whose rule is gone, so they don't count and say why ("Its rule was deleted."). Leave them out when running too.
5. **Empty pick at approve.** `run(only=[])` starts a run that does nothing. Refuse it with "Pick at least one mail, or close this to leave them all."
6. **Two kinds of pick at once.** A run start that sends more than one pick kind (inbox / message_ids / thread_ids / search) is now quietly settled by precedence. Refuse it with a plain 400.
7. **Missing run row.** If a run's `RuleJob` row is missing, the worker decides the mail with every enabled rule. Decide it with no rules instead, giving "no rule".
8. **Restore marking time.** `note_restored` uses the real clock. Pass the service clock through `mark_restored`.
9. **Missing tests:**
   - a sorting to-do (no job) next to a run with `rule_ids` still uses every rule;
   - a run whose rule is turned off or deleted mid-run decides "no rule" without crashing;
   - another run's ids, or another mailbox's ids, in `left_out`/`only` are ignored;
   - a picked thread with an offloaded mail leaves that mail out of the run;
   - the migration 0011 rename of a SUGGESTED decision's actions.
10. **Test names.** Rename the tests that still say "delete" for what is now Offload, in `backend/tests/test_rules_apply.py` and similar files.

### Task 2: Mail, offload and the permission (backend)

Fix each of these, each with a test:
1. **Resent-mail reasons.** A resent mail (Gmail removed it but CleanSync never recorded it) that fails the age or copy check is skipped with "…stayed in Gmail", which is false. Use a reason that says it is already out of Gmail and the copy is kept.
2. **Stop or restart while a batch's outcome is unknown.** The page then says "N weren't reached and stayed in Gmail". Say they may already be out of Gmail, will show in Deleted in Gmail, and their copies are kept.
3. **Crash during a rule's permanent Offload.** A crash between `adapter.delete` and the final commit leaves no `removed` mark. Record the intended `removed` together with the changes before the Gmail call, and clear it if the call fails.
4. **Restore picks.**
   - `restore_targets` ignores the label: make a `kept` view with a label work.
   - A restore sent with a Gmail view and a search must return nothing. Only `kept`/`offloaded`/`deleted` restore.
5. **Failed one-mail Offload.** It leaves a failed MANUAL decision chip when the mail wasn't in Gmail. Refuse before creating the decision.
6. **Unknown thread view.** An unknown view in `GET /api/mail/threads/{id}` falls back to IN_MAIL silently. Answer 400 for an unknown view; old aliases keep working.
7. **Fake Gmail dev tool.** The `fake_gmail` command line gets the same `DRIVESYNC_ALLOW_LOCAL_ACCOUNTS` guard as `fake_model`. Update the e2e helpers to pass it.
8. **Turn on / Turn off.**
   - Turn off also drops any pending Turn on sign-in for that mailbox, so finishing an old Google tab can't turn it back on.
   - The Turn off event includes `"status"` like the others.
9. **The offload page's Stopped state.** Expose a plain flag that an offload was stopped by the owner (for example `stopped: bool` in `offload_out`), so the page doesn't have to match on text.
10. **Missing tests:**
    - `batch_trash` with a scope 403 stays a reconnect error;
    - migration 0013 with an account that already holds the full scope reads `permanent_delete` off;
    - Turn on refused for an account that isn't connected;
    - the pretend local account Turn on;
    - the no-answer back-off escalates (1 → 5 → 15 → 60 minutes) and resets on an answer (replace the empty `assert`);
    - `in:archived` or `is:unread` sent with a CleanSync view never touches mail in Gmail;
    - the "Offloaded by you" chip text;
    - the speed test (`test_mail_speed_big.py`) with a mix of offloaded mail, and the Archived list.

### Task 3: Frontend

Fix each of these, each with a test:
1. **Circular import.** Move `mails()` (and any other shared plural helper) into a small leaf module, for example `frontend/src/lib/plural.ts`. This removes the `lib/mail.ts` ↔ `lib/ruleRuns.ts` loop. Update the imports.
2. **Old Automatic Delete forever rule.** A rule loaded with Delete forever and `mode: automatic` opens with mode set to Suggest first.
3. **Pick all in the match list.** After unticking Pick all and then ticking every match by hand, the box shows ticked, not partial.
4. **Run before Sorting has loaded.** Run on a rule card, the rule picker, and Make a rule's "Run it on older mail" stay disabled while the Sorting status is still loading, instead of treating it as "model set".
5. **ForeverJob stopped state.** Read the backend's stopped flag (Task 2 item 9) instead of matching "Stopped by you".
6. **Old `delete` kind.** A rule action of kind `delete` reaching the frontend shows and edits as Offload.
7. **One list of mail queries.** `MAIL_LISTS` in `useMailOffload` reuses the one list in `useRules`.
8. **Late Delete forever dialog.** `pickForever`'s fetch can open the dialog after the view or search changed. Drop the stale result.
9. **Search options form.**
   - When labels arrive late, an invalid Size stays in the Size field and isn't moved into the words.
   - A box with an unbalanced quote shows a short hint that later keywords are read as words.
10. **Missing tests:** the request bodies for Delete forever with permanent delete on:
    - from the reader for one mail (`view: "all"`, `message_ids`, `confirm: 1`);
    - from the picked-mail bar by hand and by Pick all.
